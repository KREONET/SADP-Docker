# 6. 자주 겪는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| CSS 를 새로 썼는데 적용 안 됨 (새 Blade 파일) | Vite 가 컴파일된 뷰(`storage/framework/views`)를 감시하지 않음 | Vite 컨테이너 재시작 (`docker restart <vite 컨테이너>`) 또는 `npm run build` |
| 화면이 깨지고 CSS 가 없음 | Vite 서버가 안 떠 있거나 포트를 못 열음 | `./scripts/dev urls` 로 주소 확인, 원격이면 SSH 터널 |
| `Unable to locate file in Vite manifest` | 빌드 파일이 없음 | `npm run build` 또는 dev 서버 실행 |
| `Snapshot missing on Livewire component` (추가/삭제 후 버튼이 먹통) | 목록의 `wire:key` 가 위치/개수에 의존하거나, 부모와 자식에 같은 새로고침 이벤트를 보냄 | 키는 DB id 처럼 안 바뀌는 값, 이벤트는 `->to(Component::class)` 로 대상 지정. AGENTS.md "Livewire conventions" 참고 |
| 버튼 높이가 이상함 / 찌그러짐 | `h-8 w-8` 처럼 높이만 토큰을 따름 | `size-8` 사용 |
| `h-8!` 로 쓴 높이가 밀도 설정을 안 따름 | 보정이 레이어 밖에 있음 | `@layer base` 안에 `!important` 로 (03 문서) |
| 한국어가 안 나옴 | 키 불일치 / JSON 오류 | [번역 문서](04-번역.md) 의 "자주 하는 실수" |
| `KoreanTranslationsTest` 실패 | `__()` 문구가 `ko.json` 에 없음 | 실패 메시지에 나온 키를 추가 |
| `NoNativeBrowserDialogsTest` 실패 | `wire:confirm`, `confirm()`, `alert()` 사용 | `<x-modal-confirmation>` 으로 교체 |
| 테스트에서 `InstanceSettings` 오류 | 설정 행(id=0)이 없음 | `beforeEach` 에서 `InstanceSettings::forceCreate(['id' => 0]); Once::flush();` |
| 테스트 사용자가 `/platform` 에서 403 | 플랫폼 관리자가 아님 | 루트 팀(id=0)의 admin 또는 owner 로 만든다 |
| 브라우저 테스트가 안 끝남 | 이전 Playwright 서버가 남음 | `pkill -f "playwright run-server"` 후 재실행 |
| 시스템에 `php` 가 없다고 나옴 | 컨테이너 밖에서 실행함 | `./scripts/dev exec php artisan …` |

## 막혔을 때 확인 순서

1. 브라우저 개발자 도구 콘솔의 오류
2. `./scripts/dev logs` (앱 로그), `storage/logs/`
3. `/platform/logs` 에서 시스템 로그 (켜져 있다면)
4. 관련 테스트 파일을 열어 보기: 테스트는 "이 코드가 어떻게 쓰이는지"의 가장 정확한 예제입니다.

## `id = 0` 은 버그가 아닙니다

루트 팀, localhost 서버, 인스턴스 설정은 기본 키가 `0` 인 특별한 행입니다. 바꾸거나 "고치지" 마세요. 새로 만드는 일반 행에 `0` 을 쓰면 안 됩니다. (AGENTS.md "Instance sentinels")

## APP_KEY 교체, 백업 암호화, 서버 경로 가져오기

### APP_KEY 를 바꾸려면 (`security:rotate-app-key`)

DB 의 비밀 값(SSH 개인 키, 데이터베이스 비밀번호, S3 키, 알림 토큰, 환경 변수, 2단계 인증 비밀, 백업 암호 등)은 `APP_KEY` 로 암호화되어 있습니다. 키만 바꾸면 기존 값을 읽을 수 없으므로 아래 순서를 지킵니다.

1. Coolify DB 와 `/data/coolify/source/.env` 를 백업합니다.
2. 새 키를 만듭니다: `php artisan key:generate --show`
3. `.env` 에서 `APP_PREVIOUS_KEYS` 에 **기존** `APP_KEY` 값을, `APP_KEY` 에 **새** 키를 넣습니다. (이전 키가 여럿이면 쉼표로 구분, 최신 키를 앞에)
4. Coolify 를 재시작합니다. Laravel 은 이전 키로도 자동 복호화하므로 교체 중에도 서비스가 동작합니다.
5. 미리 확인: `php artisan security:rotate-app-key --dry-run`
6. 실제 교체: `php artisan security:rotate-app-key` — 모든 암호화 값을 새 키로 다시 저장합니다. 여러 번 실행해도 안전하며(이미 새 키인 값은 건너뜀), 결과 표의 `Failed` 가 0 이 될 때까지 확인합니다.
7. 캐시 비우기: `php artisan optimize:clear`
8. 대기 중인 작업, 세션, Sentinel 토큰(서버의 Sentinel 토큰을 재발급)이 정리된 뒤 `APP_PREVIOUS_KEYS` 를 지우고 다시 재시작합니다.

명령은 `encrypted` / `encrypted:array` 캐스트, `EncryptedArrayCast`, 그리고 직접 암호화하는 열(GitLab 웹훅 토큰, OAuth client secret, MongoDB 초기 root 비밀번호, 2단계 인증 비밀/복구 코드)을 모델에서 자동으로 찾습니다. 새 모델에 암호화 열을 추가할 때 캐스트를 쓰면 따로 등록할 필요가 없고, 접근자로 직접 암호화한다면 `RotateAppKey::MANUALLY_ENCRYPTED_COLUMNS` 에 추가합니다.

### 데이터베이스 백업 암호화 (선택)

- 백업 일정 편집 화면의 "Encrypt backup files" 또는 API 의 `encrypt_backup` 으로 켭니다. 기본값은 꺼짐입니다.
- 켜면 덤프 직후 서버에서 `openssl enc -aes-256-cbc -pbkdf2 -iter 600000 -salt -md sha256` 으로 암호화하고 평문 덤프는 지웁니다. 파일 이름 끝에 `.enc` 가 붙습니다. 서버에 `openssl` 이 있어야 하며, 없으면 백업이 실패합니다(평문을 남기지 않음).
- 암호(passphrase)는 백업 파일마다 무작위로 만들고 Coolify DB 에 `APP_KEY` 로 암호화해 저장합니다. 명령줄(`ps`)과 로그에는 나오지 않습니다(stdin 으로 전달).
- Coolify 의 가져오기(서버 경로 또는 S3)로 복원하면 자동으로 복호화합니다. **다운로드한 파일은 암호화된 그대로입니다.** 직접 업로드한 `.enc` 파일은 복원할 수 없으니 먼저 복호화하세요.
- Coolify 자체 DB(`coolify-db`) 백업은 암호화할 수 없습니다. 암호가 그 DB 안에 있어서, DB 를 잃으면 백업도 풀 수 없기 때문입니다. 같은 이유로 백업 실행 기록(executions)을 지우면 그 백업의 암호도 사라집니다.

### 서버 경로에서 가져오기가 거부될 때

서버 파일 경로로 DB 를 가져올 때는 허용된 디렉터리 안의 파일만 읽습니다. 기본은 `/data/coolify/backups` 이고, `.env` 의 `DATABASE_IMPORT_ALLOWED_PATHS=/srv/db-dumps,/mnt/backups` 처럼 쉼표로 추가합니다(`config/database-import.php`). 경로는 서버에서 `realpath` 로 심볼릭 링크까지 풀어서 확인하므로, 허용 디렉터리 안의 링크가 바깥을 가리키면 거부됩니다. 허용 디렉터리는 링크가 아닌 실제 경로로 적으세요.
